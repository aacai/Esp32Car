# ESP32-C3 小车通信协议文档

> 面向 App / 上位机开发。本文档描述小车（固件 `main/`）对外暴露的**全部控制接口**，
> 包括 **BLE（低功耗蓝牙）** 与 **WiFi HTTP（网页/REST）** 两种通道。
> 两种通道**共用同一套指令字符集**，行为一致。

---

## 0. 总览

| 通道 | 用途 | 连接方式 | 指令下发 | 状态获取 |
|------|------|----------|----------|----------|
| **BLE** | 手机直连小车（无需路由器） | GATT，设备名 `EspCar_XXXXXX` | 写指令特征（无响应写） | 读 / 订阅通知（JSON） |
| **WiFi HTTP** | 同局域网或连小车热点 | TCP，HTTP GET | `GET /api?c=X` | `GET /status`（JSON） |

- 设备名：`EspCar_` + MAC 后 3 字节（大写十六进制），例如 `EspCar_FE1036`。
- 小车同时在线：BLE + 自带 AP（`EspCar_XXXXXX`，密码 `12345678`，IP `192.168.4.1`）+ STA（连外部 WiFi）。
- 指令在车端由 `car_control()` 统一解析，BLE 与 WiFi 完全等价。

---

## 1. 指令字符集（两种通道通用）

单字节 ASCII 字符。可一次发送**多个字符**（依次执行），例如 `c=FLR` 会依次执行前进→左转→右转。

| 指令 | 含义 | 车端行为 |
|------|------|----------|
| `F` / `f` | 前进 | 两轮前进 |
| `B` / `b` | 后退 | 两轮后退 |
| `L` / `l` | 左转 | 右轮前进、左轮后退（差速左转） |
| `R` / `r` | 右转 | 左轮前进、右轮后退（差速右转） |
| `S` / `s` | 停止 | 两轮断电、PWM 置 0 |
| `0`~`9` | 设置速度 | 速度 = 数字 × 10（%），即 `0`→0%、`5`→50%、`9`→90% |

- 速度立即生效，影响**后续**运动指令；不会改变当前已执行的动作方向。
- 未知字符被忽略（车端仅打印 warning，不报错、不断连）。
- `last_cmd` 记录最近一次有效指令；`cmd_count` 为累计有效指令数（每次有效指令 +1，含速度设置）。

> 示例：
> - 只发 `F` → 以当前速度（默认 60%）前进。
> - 先发 `8` 再发 `F` → 以 80% 速度前进。
> - 发 `F` 后长时间不发的 `S` → 车会一直前进（**无自动超时停止**，App 建议做"松手即停 / 心跳超时"逻辑）。

## 2. BLE 通道（推荐手机直连用）

### 2.1 服务与特征

- **设备名（GAP）**：`EspCar_XXXXXX`（可被发现，通用可发现模式）。
- **主服务 UUID**：`0000abcd-0000-1000-8000-00805f9b34fb`（16-bit `0xABCD`）。
- **指令特征（CMD）**：`00001234-0000-1000-8000-00805f9b34fb`（16-bit `0x1234`）
  - Properties：`Write` + `Write Without Response`（`F_WRITE | F_WRITE_NO_RSP`）。
  - **建议用「无响应写（Write Without Response / WriteCommand）」**：NimBLE 稳定接受，且不会触发加密/配对流程（见 §5 注意事项）。
- **状态特征（STATUS）**：`00001235-0000-1000-8000-00805f9b34fb`（16-bit `0x1235`）
  - Properties：`Read` + `Notify`。
  - 手机**订阅 Notify** 后，每当连接建立、收到指令、状态变化时，车主动推送一份完整状态 JSON（见 §3）。

> 注意：不同平台 UUID 文本大小写不敏感；完整 128-bit 形式固定为上面的值，
> **不要用「末尾匹配 1234」去查找**——`1234` 在中间，应做「包含匹配」。

### 2.2 发送指令（写 CMD 特征）

- 写入数据为 1~N 字节 ASCII，每字节即一个指令字符（见 §1）。
- 例：写入 `0x46`（`'F'`）即前进；写入 `"FL"`（两字节）即先前进再左转。
- 写成功后车**自动推送一次状态 Notify**（含更新后的 `last_cmd`/`action`/`cmd_count`）。

### 2.3 读取 / 订阅状态（STATUS 特征）

- **Read**：直接读返回当前完整状态 JSON 字符串（UTF-8）。
- **Notify**：连接后订阅，车在以下时机自动推送：
  - 连接建立瞬间；
  - 每次收到指令并执行后；
  - 状态内部变化（WiFi 连接/断开、扫描刷新等）。
- 推送内容 = §3 的 `car_status_json` 结构。

### 2.4 BLE 配对说明（重要）

- 车使用 **Just Works** 配对（无 PIN、无弹窗），地址类型为 **Public**（稳定不变）。
- GATT 特征**不要求加密**：纯连接（不配对）即可收发 `F/B/L/R/S`，无需先配对。
- 安卓在蓝牙设置里点设备会强制发起配对，车端能静默完成绑定（密钥存 NVS，重连免配对）。
- 见 §5「App 开发注意事项」中关于写模式与加密的坑。

## 3. 状态 JSON 结构（BLE Notify/Read 与 WiFi `/status` 共用）

字段名固定为以下英文键（注意 `ip` 不是 `wifi_ip`）：

```json
{
  "ip": "192.168.50.100",        // STA 获取到的局域网 IP；未连上为 "0.0.0.0"
  "uptime": 373,                 // 上电后秒数（uint64）
  "free_heap": 99520,            // 剩余空闲堆内存（字节）
  "last_cmd": "F",               // 最近一次有效指令字符
  "action": "前进",              // 当前动作中文：前进/后退/左转/右转/停止
  "speed": 60,                   // 当前速度百分比 0~100
  "cmd_count": 1,                // 累计有效指令数
  "ble": 1,                      // BLE 当前是否已连接（1/0）
  "ble_adv": 0,                  // BLE 广播状态（0=正常广播，<0=启动失败码）
  "wifi_state": "connected",     // WiFi 状态：off/scanning/connecting/connected/disconnected/error
  "scan": [                      // 车视角扫描到的 WiFi 列表（可能为 [])
    {
      "ssid": "ImmortalWrt-2.4G",
      "rssi": -44,               // 信号强度 dBm（越接近 0 越强）
      "chan": 5,                 // 信道
      "auth": 4,                 // 加密方式枚举（见下）
      "target": 1                // 是否为配置的 target SSID（1/0）
    }
  ],
  "wifi_log": [                  // WiFi 连接过程日志（时间顺序，最近若干条）
    "WiFi 已启动，准备扫描",
    "已找到目标 SSID，连接中",
    "WiFi 已连接，IP=192.168.50.100"
  ]
}
```

**`auth` 枚举值对照**（与 ESP-IDF `wifi_auth_mode` 一致）：

| 值 | 加密 |
|----|------|
| 0 | OPEN（开放） |
| 1 | WEP |
| 2 | WPA_PSK |
| 3 | WPA2_PSK |
| 4 | WPA_WPA2_PSK |
| 5 | WPA3_PSK |
| 6 | WPA2_WPA3_PSK |
| 其他 | 保留/? |

> 字段顺序与数量可能随固件版本微调，App 端建议**按 key 解析、忽略未知 key、对缺失 key 给默认值**。

## 4. WiFi HTTP 通道

小车内置 HTTP 服务器（端口 80）。两种接入方式：
- **连小车热点**：手机/电脑连 `EspCar_XXXXXX`（密码 `12345678`），访问 `http://192.168.4.1/...`
- **同局域网**：车连上外部 WiFi 后，访问 `http://<车IP>/...`（如 `http://192.168.50.100/`）。

所有响应均带 `Access-Control-Allow-Origin: *`，支持跨域（便于网页/前端直接 fetch）。

### 4.1 `GET /` — 遥控主页
返回 `index.html`（含方向按钮 + 实时状态面板）。App 一般无需此接口，仅供浏览器遥控。

### 4.2 `GET /api?c=<cmd>` — 下发指令
- `c` 参数：指令字符（同 §1），可多个连续，如 `/api?c=FB`、 `/api?c=F`。
- 每个字符依次调用 `car_control()`。
- 响应：`{"ok":1}`（JSON），HTTP 200。
- 例：
  ```
  GET /api?c=F      → {"ok":1}    前进
  GET /api?c=8      → {"ok":1}    速度设为 80%
  GET /api?c=S      → {"ok":1}    停止
  ```

### 4.3 `GET /status` — 完整状态
- 响应：§3 的完整状态 JSON（同 BLE 推送内容）。
- 建议 App 轮询间隔 ≥ 500ms，或优先用 BLE Notify / 网页 WebSocket 类机制。

### 4.4 `GET /mylog?from=<N>` — 增量日志
- `from`：上次返回的游标（首次可不传或 `from=0`），用于增量拉取固件运行日志。
- 响应：日志 JSON（含 `next` 游标，下次传回 `from=next` 获取新日志）。
- 用途：调试、排错，正常控制流程可不依赖。

## 5. App 开发注意事项（踩坑总结）

1. **BLE 写用「无响应写（Write Without Response）」**
   指令特征虽同时支持有/无响应写，但用「有响应写（Write Request）」在已配对（bonding）场景下
   会触发 macOS/iOS 加密流程，可能因地址/密钥不匹配导致连接断开。无响应写稳定且车端照常执行。
   - Android（BluetoothGatt）：`writeCharacteristic(char, value, BluetoothGattCharacteristic.WRITE_TYPE_NO_RESPONSE)`
   - iOS（CoreBluetooth）：`writeValue(_:for:type:.withoutResponse)`

2. **UUID 匹配用「包含」而非「末尾」**
   完整 128-bit UUID 形如 `00001234-0000-1000-8000-00805f9b34fb`，短号 `1234` 在中间。
   查找特征时应对整串做「包含 `1234`」判断，不要 `endsWith("1234")`。

3. **状态 JSON 可能超过 3KB**
   BLE 单次 Notify 有 MTU 限制（默认 23 字节，协商后可更大）。若 App 收到被截断的 JSON：
   - 自行做**分片重组**（按通知累积直到得到完整 JSON）；
   - 或订阅后直接 `Read` 一次完整状态（Read 不受单包 Notify 长度限制，车端会返回完整 8192 缓冲）。
   - 建议优先 `Read` 拿全量，Notify 仅作"状态已变化"的触发信号。

4. **无自动停止**
   车收到 `F` 后会一直前进直到收到 `S` 或新方向指令。App 应实现：
   - 按键"按下发指令、松开发 `S`"（触控/方向键常用）；
   - 或心跳：超过 N 秒未收到新指令自动补发 `S`，防止失控。

5. **`last_cmd` 是单字符**
   多字符指令会逐个执行，`last_cmd` 只记录最后一次有效字符；连续动作请用多个独立写/请求。

6. **WiFi 字段名是 `ip`**
   `/status` JSON 里局域网 IP 的键是 `ip`，不是 `wifi_ip`。

7. **BLE 与 WiFi 并存**
   两条通道同时可用，App 可任选其一或双通道热备（如先试 WiFi，连不上再 BLE）。

## 6. 最小可用流程示例

### BLE（伪代码）
```
1. 扫描设备名前缀 "EspCar_"
2. 连接
3. 发现服务 0000abcd-...，取特征：
     cmd    = 00001234-...  (WriteWithoutResponse)
     status = 00001235-...  (Notify)
4. 订阅 status 的 Notify
5. 写 cmd: "F"        // 前进
   收到 Notify(JSON): last_cmd="F", action="前进", cmd_count=1
6. 写 cmd: "S"        // 停止
   收到 Notify(JSON): last_cmd="S", action="停止", cmd_count=2
7. 断开
```

### WiFi HTTP（伪代码）
```
GET http://192.168.50.100/api?c=F     → {"ok":1}
GET http://192.168.50.100/status       → JSON(last_cmd="F", action="前进", ...)
GET http://192.168.50.100/api?c=S      → {"ok":1}
```
